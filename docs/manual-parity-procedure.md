# 10월 8일 수동 발행에서 확인한 실행 절차

매일 실행에서 다음 순서를 적용한다. 로컬 명령의 사용 가능성을 클라우드에 가정하지 않는다.

1. 발행일은 실행 당시 한국 날짜로 정한다. 같은 날짜의 보고서·검증표·목록이 이미 원격에 있으면 내용을 읽어 확인하고 중복 발행하지 않는다. 일부만 있거나 내용이 충돌하면 덮어쓰지 않고 알린다. 과거 대화의 실패 기록보다 현재 원격 상태를 우선한다.
2. 국내 신문사에서 후보를 찾은 뒤 기관 상세 본문과 공개 첨부 PDF를 대조한다. 웹 도구의 읽기 오류와 원문 접근 제한을 구별한다. 상세 페이지 파싱이 실패하면 페이지에서 확인한 공식 첨부 링크나 공식 재게시본을 사용한다. 실행 환경이 지원할 때만 일반 공개 다운로드·텍스트 추출을 사용한다. 원문을 끝내 읽지 못하면 보류한다. 로그인·유료벽·보안 차단을 우회하지 않는다.
3. 출처표와 주장 대조표를 먼저 채우고, 그 범위 안에서 짧은 독자적 보고서를 작성한다. 통계 합계와 구성 항목, 분모·단위·대상 월, 발표일과 시행일을 확인한다. 사실뿐 아니라 용어 정의와 생활 설명도 직접 읽은 근거를 붙인다. 원문 내부의 충돌 수치는 제외한다. 기존 원고의 표현도 그대로 믿지 말고 재검증한다.
4. 두 문서 전체를 보존하고, 날짜·필수 제목·본문 및 근거 링크·검증표 상대 경로를 검토한다. 로컬에서는 scripts/preflight-publication.mjs를 사용한다. 클라우드에서는 같은 buildFiles 검사를 수행하는 Financial Summary Writer의 save_daily_summary에 date, report, evidence만 전달한다. 각 문서는 100자 이상, UTF-8 150KB 이하이며 빈칸이나 생략 표시로 원고를 대체하지 않는다. 형식 검사는 사실 검증이 아니다.
5. 클라우드 저장기는 보고서·검증표·주제별 목록을 한 커밋으로 저장하고 해당 커밋의 내용을 다시 읽어 검증한다. 임의 경로·별도 GitHub 쓰기 도구·로컬 컴퓨터를 요구하지 않는다. 플랫폼의 쓰기 승인 절차는 그대로 따른다.
6. saved=true, 실제 commit과 urls가 반환돼야 저장 성공이다. already_present=true는 기존 동일 원고 확인이며 새 발행으로 세지 않는다. 가능하면 반환된 커밋 URL의 두 문서와 날짜별 블로그를 읽어 확인한다. 저장 성공과 블로그 표시 확인 여부를 따로 보고한다.
7. 오류를 연결/인증/문서 형식/기존 내용 충돌/플랫폼 안전 검사/기타로 구분하되 반환된 근거가 없으면 원인 미상으로 쓴다. 도구명·단계·제공된 오류 원문을 검증 기록과 결과에 남긴다. 승인 또는 안전 검사 차단은 반복하거나 다른 경로로 우회하지 않는다. 원고를 보존하며, 실패만을 이유로 예약을 비활성화하지 않는다.

국내 우선, 국내 신문사 5곳 탐색, 신규 3건 미만이면 최근 7일 미발행 보충, 사회초년생을 위한 쉬운 해설, 18:00 마감은 기존 편집 원칙대로 유지한다. 오늘의 구체적인 기사·수치는 다음 실행에 재사용하지 않는다.
