# 매일 실행 절차

## 일정

매일 18:30 Asia/Seoul에 시작한다. 당일 주간 발표를 모아 저녁에 읽기 위한 편집상의 선택이다. 모든 기관의 발표가 종료되는 시각이라는 뜻은 아니다. 기본 마감은 18:00이며, 그 뒤 발표는 다음 호에서 다룬다.

발표 시간이 없으면 임의의 시각을 부여하지 않는다. 마감 전에 직접 관찰한 기록이 있으면 그 시각을 근거로 사용한다. 같은 날 날짜만 있는 자료를 마감 후 처음 확인했다면 다음 호의 '발표 시각 미상·이번에 확인' 항목으로 넘긴다. 처음 시작한 날의 시범 자료는 정기 발행과 구분한다.

## 실행

1. 실제 현재 시각과 Git 상태·원격을 확인한다. `AGENTS.md`와 편집 원칙을 읽는다. 이전 보고서·검증표를 살펴 중복과 누락을 확인한다.
2. 직전 정상 마감부터 이번 마감까지 후보를 탐색한다. 전일 실행 실패로 24시간보다 길어졌다면 기간을 보고서에 명시한다. 오래된 자료는 '보충'으로 분리한다. 과거 날짜의 발행을 위조하지 않는다.
3. 금융위원회·금융감독원·한국은행을 기본으로 확인하고, 국내 언론 경제·금융 기사 검색과 관련 해외 공식 발표를 확인한다. 분야별 결과와 접근 실패를 남긴다.
4. 금융소비자에게 중요한 변경, 정책·금리·금융안정, 금융회사 주요 공시 순으로 중요도를 판단한다. 원문을 열어 3~5개 후보를 고르되 검증된 항목만 남긴다.
5. `templates/evidence.md`로 `evidence/YYYY/MM/YYYY-MM-DD.md`를 작성한다. 원문을 확인한 사실 문장만 `briefings/YYYY/MM/YYYY-MM-DD.md`에 쓴다. 접근 불가·날짜 불명·출처 충돌은 보류한다.
6. 쉬운 설명과 표·도식도 원문에 대조한다. 가능하면 각 호에 이해를 돕는 시각 자료를 넣되 장식용 이미지를 억지로 추가하지 않는다. 도식의 텍스트 대안을 제공한다.
7. 아래 발행 전 검토를 완료한다. 확보한 항목이 없으면 수집 상태만 발행하고 그 이유를 밝힌다. 일부 출처만 확인했다면 '부분 수집'으로 명시한다.
8. `briefings/README.md` 목록을 갱신한다. 기존 같은 날짜 보고서가 있으면 변경 필요성을 확인하고 중복 발행하지 않는다. 수정은 정정 기록을 추가한다.
9. 변경 파일을 읽어 검토하고 `git diff --check`를 실행한다. 자신의 해당 보고서·검증표·시각 자료·목록만 명시적으로 스테이징하고 커밋한다. origin을 확인한 뒤 현재 추적 브랜치에 일반 push한다. 원격 변경으로 거절되면 강제 푸시하지 말고 보존 후 알린다.
10. 새 보고서 완료, 정정, 실패 또는 사용자 조치 필요 시 링크와 상태를 알린다. 재실행에서 바뀐 것이 없으면 조용히 종료한다.

## 발행 전 검토

- 모든 사실·정의·그림 주장에 직접 열람한 근거가 있는가?
- 원문과 수치·날짜·단위·대상·조건·결정 상태가 일치하는가?
- 발표 시각과 실제 확인 시각을 지어내지 않았는가?
- 원문을 읽지 못한 내용을 검색 요약으로 대체하지 않았는가?
- 제목, 도표, 쉬운 설명에 원문 이상의 결론이 들어가지 않았는가?
- 복제한 기사·사진·도표, 불필요한 인용이 없는가?
- 실제 확인 범위, 누락, 발행 시각이 보고서에 드러나는가?

검토는 작성 에이전트의 원문 대조이며 독립된 전문가 검수를 뜻하지 않는다. 근거가 남아 있어야 이후 오류를 추적하고 정정할 수 있다.
